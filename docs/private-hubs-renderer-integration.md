# Live renderer integration status

The ordinary renderer implements the saved-document handoff, and the main host owns the transition singleton and close/quit integration. The macOS development build enables **File → Create private copy…** and **File → Open private hub…** for the first password-based private-hub workflow. The private gallery includes collections and sorting, encrypted notes/tag/rating editing, in-window original-video playback, per-video preview regeneration, automatic locking, authenticated password changes and verified unprotected copies. Touch ID is deferred. See the [first-build guide](./private-hubs-first-build.md) for supported operations and review directions; this is not a production release.

## Implemented

- Home uses the dedicated request/snapshot/release channels through the reviewed preload allowlists. Each active writable hub supplies its full catalogue, even when clean; only no-hub and read-only sessions supply `null`. The projection includes notes, source locations, manual tag definitions/colors, automatic tags and screenshot settings.
- A shared renderer mutation lifetime records every persisted edit, including repeated writes to an already-true dirty flag. Image, automatic-tag and manual-tag services guard their mutators. Save acknowledgements clear bookkeeping without replacing live tag arrays.
- The catalogue editor registers a synchronous row-tag draft flusher. Valid drafts, including rows outside the current filter, commit before the frozen revision is captured. Invalid tag paths refuse the handoff. Unapplied bulk commands remain unapplied.
- Composition tracking refuses the handoff while IME text entry is unfinished. The DOM guard blurs the active input before snapshotting, makes the entire body inert (including Material overlays), blocks editing/clipboard/drag events, pauses ordinary media and disables existing autoplay. Delayed clip playback, reload retries and detached clips also check their captured mutation lifetime.
- Editor, tag-tray and Home confirmation callbacks retain their original mutation epoch. Pausing invalidates them permanently, including after handback. Existing dialogs close during handback, after main admission resumes.
- Native invokes retain a renderer pending hold through their immediate `.then`/`await` consumers, until the next event-loop task. Handoff is refused while a hold or ordinary save/close request is pending. Direct asynchronous clipboard writes also retain a hold. Future consumers that defer model application beyond that task must retain an explicit hold through the entire update.
- Incoming ordinary IPC callbacks are deferred while frozen, then replayed in order. They invalidate the saved revision and are never silently discarded. Unsubscribed listeners stay unsubscribed. A partially applied failing callback is not retried: the editor is quarantined.
- The native factory prepares the release after private disposal, restores the normal window while still paused, reopens main admission, then sends the renderer release. A failed release send re-seals normal admission. Optional monitoring/queue refresh remains separate from this critical handback.

## Connected host lifecycle

- `main.ts` owns one `PrivateApplicationWorkspace`; constructing it opens no files, sessions or windows. Its native File entries refuse inherited ordinary operation scopes and add no ordinary renderer capabilities.
- Normal close, shutdown and window-all-closed paths delegate to the active private transition before sending `please-shut-down-ASAP`. Private disposal and normal restoration must finish before the ordinary save/quit flow retries.
- Only a main-proven Keep Working choice or close-save failure acknowledges an abandoned quit. The notification captures the original window, frame, navigation and catalogue authority, rather than trusting a separate renderer cancellation message.
- Normal catalogue-open requests received during private use stay in a bounded, deduplicated memory queue. They obtain filesystem authority only after returning to normal admission. A pending private quit continues to defer those requests and blocks renderer catalogue changes and source checks until the main process confirms Keep Working or a close failure; a settings-error dialog cannot let a new hub replace its original owner.
- After clean settlement, a fresh main operation resets transient renderer progress, restores source monitoring and dispatches deferred normal opens. The renderer preserves catalogue edits and source grants while clearing interrupted scan/generation indicators.

## Private gallery

The isolated gallery supports paged browsing, title/tag search, All videos/Favourites/Recently played collections, seven sort choices, selected video details, explicit notes/tag/rating Save and Discard, encrypted clip playback, explicit original-video playback, on-demand filmstrip viewing, preview regeneration with cancellation, encrypted inactivity settings, and locking. A separate preload exposes only list, detail, save, playOriginal, stopOriginal, regenerate, cancelRegeneration, sources, addSource, connectSource, disconnectSource, relocateSource, cancelSourceConnection, importVideo, scanSource, importProgress, cancelImport, protection, setProtection and lock. Main validates the exact live window/frame/generation, limits metadata and page size, issues per-window selection/revision IDs, and rejects stale completions. No normal preload, source paths, keys or full catalogue are supplied to this renderer. Ordinary file actions remain outside this bridge.

The existing `list` method accepts optional fixed collection/sort/direction selectors; no additional IPC method or response field is exposed. Main filters and orders bounded cached row projections, leaving source paths and numeric sort metadata in main. Favourite membership uses saved `stars === 5.5`; Recently played includes only valid positive saved last-played dates and initially orders newest first. Original playback can add encrypted history when explicitly enabled in Protection; previews never do. Missing or invalid numeric metadata remains last in either direction, and equal keys retain catalogue order without replacing selection IDs. Detail/save/regeneration reprojection refreshes membership and sort keys.

The labelled Collection, Sort by and direction controls reset pagination and retire stale list responses, retries and image jobs. They preserve the current search and retain the chosen view during metadata refresh. Notes/tag drafts, text composition, active operations and unsaved Protection settings block changes; rejected actions restore the current controls. Browse choices stay in page memory and reset to All videos/catalogue/ascending on lock or a new private window. Filtering and sorting introduce no catalogue/settings/history writes, original-file reads or source grants. The usual encrypted preview requests and inactivity rules still apply.

Protection's `resetPlaybackHistory` request accepts only `lastPlayed` or `timesPlayed`. The trusted controller owns the count-only native confirmation, with Cancel as default, and a dedicated disposal drain. The storage transaction holds the serial queue through confirmation and guarded encrypted publication. Zero changes avoid confirmation and writing. The response contains only a fixed status and, after a reset, a bounded count. Video edits, composition and unsaved Protection/credential drafts block the UI action. Settled attempts retire selection and cached IDs and refresh the existing collection/query/sort while preserving Protection feedback. Lock remains available; replies after revocation are ignored. Resetting keeps the recording preference unchanged and does not claim erasure of encrypted recovery backups or separate copies.

The session performs each metadata edit as a queued read/compare/write transaction against the selected row's complete private revision. Changed rows conflict instead of being overwritten; unrelated catalogue fields and legacy tag strings survive. Storage rechecks the captured authority before encrypted publication. Oversized persisted metadata stays read-only, and browser navigation cannot silently discard a draft. Lock clears drafts immediately and invalidates late save responses; a write already admitted to the filesystem may have completed.

Regeneration accepts only an issued ID/revision and uses a native picker for the preferred source root from encrypted storage. Grants stay in main-process memory and expire with the browser; root replacement invalidates reuse. A pending picker is drained during teardown and cannot grant access after cancellation. Dirty drafts refuse generation; accepted jobs stop playback and hold editing/navigation until completion, while Cancel and Lock remain available. Failed descriptor closure or an unconfirmed decoder exit revokes the session and prevents normal restoration. Changed preview geometry and ordinary file-management actions remain unavailable. Selected-video import uses its own encrypted transaction. Source relocation has its own reviewed transaction through Source folders.

**Play video** submits only the selected ID/revision through `playOriginal`; **Play preview** continues to use an authenticated encrypted clip. The main process rereads the selected row and saved source location around the native folder picker, reuses only a current session grant, and captures a branded no-follow source descriptor. The renderer receives one random 64-hex `theatrum://app/original/` capability URL, never a source path or filename. The private protocol serves only the active capability with no-store GET/HEAD and single-range responses, bounded reads and at most two active streams. Source identity and operation authority are rechecked before delivery. Original files remain outside encrypted storage.

`stopOriginal` cancels a pending picker or revokes active playback synchronously and tracks its read/descriptor drain. Selection, details closure, catalogue operations, protection/source operations, regeneration and locking retire playback; unconfirmed cleanup quarantines the private workspace. The UI removes the video source before those transitions, keeps Cancel and Lock available during opening, and rejects stale promise/media callbacks. Read-only playback preserves notes/tag drafts, writes no played metrics and does not renew inactivity. The player uses `preload="none"`, separate Play video/Play preview buttons and explicit Stop controls, with download, remote playback and picture-in-picture controls disabled. MP4/M4V, MOV, WebM and Ogg containers are admitted, subject to bundled codec support; failures show fixed text with no external-player or transcoding fallback.

Fullscreen permission is limited to the active hub browser’s exact main frame at `theatrum://app/index.html`, with matching request URL and, for permission checks, origin. Password/conversion windows and other permissions remain denied. Native player fullscreen needs no additional file, capture, pointer-lock or keyboard-lock access. Escape leaves details available; stopping/clearing a fullscreen video requests exit without delaying source revocation or locking. Native tests wait for macOS’s completed entry/exit events before testing subsequent actions.

The Source folders panel lists at most 256 saved roots through opaque window-owned IDs, generic numbered labels, catalogue reference counts and session connection status. It does not expose source paths or persist connection settings. Listing an ungranted root performs no filesystem probe; only a previously authorised grant can be checked for continued directory identity. Connect uses the existing native picker, rereads encrypted source identity before and after selection, shares the gallery's pending gate and rejects late cancellation or revocation. Disconnect retires the memory grant, and locking drains an outstanding picker before ordinary restoration. Connect and Disconnect keep saved locations unchanged. Change location uses the separate guarded relocation transaction described below. Add folder uses a native directory picker and an encrypted source-table append; it saves a disconnected root without enumerating contents. Add videos uses a native picker for at most 100 files and serial encrypted import transactions; it does not grant recursive scanning or watcher access. The entire path list is validated and copied before source probes. Each file rechecks catalogue/source authority, and its descriptor drains before counting completion or starting the next file. Duplicates are skipped without media reads; an ordinary unreadable file can fail independently. Cancellation retains completed entries, while source changes and uncertain cleanup stop the batch. Numeric-only importProgress polling is the sole read allowed through a pending import; it supplies no filenames and does not renew the idle timer. The preload and UI reject late polls after completion, cancellation or locking and show the known imported, duplicate, failed and unprocessed counts.

**Find new videos…** uses the separate `scanSource` capability with the same opaque source ID and live window/frame/generation checks. After a source grant, main discovers new paths using directory entries and file metadata only, skips linked/ignored/`vha-` folders and already catalogued paths, and presents a count-only native confirmation with Cancel selected by default. The candidate review stays in main. At most 100 videos enter one reviewed batch; the confirmation indicates when another scan can find more. Traversal limits are 10,000 entries, 1,000 directories and depth 32; hitting a limit returns `scan-limit` and directs the user to manual selection. An empty scan returns `nothing-new`.

Discovery uses path-based traversal with directory-identity checks before and after access. Candidate file/ancestor identities and catalogue source configuration remain bound through confirmation and import capture. This is replacement detection and authority checking, not descriptor-relative traversal or an OS filesystem sandbox. Confirmed candidates reuse serial encrypted imports and the existing cancellation/drain path. Progress is idle until confirmation and then returns counters only; completed entries survive cancellation. The preload permits `importProgress` and one-shot `cancelImport` during both scan and manual-import requests. Draft/navigation guards and stale-response cleanup remain shared. Opening the source panel or adding a source folder never starts discovery, and no watcher is enabled.

The separate `refreshVideo` capability accepts only the same opaque `{id, revision}` pair used for preview regeneration. Details explicitly report `refreshable`; the initial implementation requires one saved location and a unique existing preview hash. Main checks the saved row and source configuration before and after native authorization, captures the source under a fresh random preview namespace, and calls the session’s guarded refresh transaction. No replacement path, technical metadata or hash is accepted from the renderer.

Refresh shares the generation pending/cancellation/drain path, stops playback and requires saved/discarded drafts. Its new previews and measured technical fields become reachable through one catalogue replacement. Main reconciles the selected row from storage after an admitted outcome, including cancellation after publication, and rotates edit and media revisions. The UI reloads saved details after uncertain outcomes, discards stale media sources and refreshes the current collection/order. A lost or replaced selection cannot retain editing authority. Lock remains available; decoder and descriptor cleanup must finish before restoration.

The separate `checkSource` action accepts one opaque source ID and shares the source-operation cancellation channel. It checks only saved locations after native root authorization, without importing or repairing anything. Its count-only response has `total`, `sameSize`, `differentSize`, `missing`, `unverified` and `ignored`; the five categories must sum to total and every value is bounded to 10,000. Main rechecks saved reference/configuration identity before reporting, and never exposes the helper revision or native paths. The UI retains selected-video drafts and gallery IDs, refreshes connection state, and shows the point-in-time size-comparison limitation. Cancel/Lock discard partial or late responses; pending filesystem access and native selection still drain before restoration. Reports clear on source-panel refresh, close or locking and are not persisted.


`relocateSource` accepts only an issued source ID. Its native picker selects the new root, a branded main-owned review checks the referenced relative files and recorded sizes, and a native confirmation identifies the selected path and video count. All prompts, review work and the save share the existing pending/cancellation/drain boundary. No replacement path or review object crosses private IPC. The UI requires saved/discarded drafts and refreshes gallery/source IDs for every outcome, including ambiguous cancellation.

The session reserves write admission before queueing, rereads the authenticated catalogue, compares source/reference identity, revalidates reviewed file metadata, and atomically changes only `inputDirs[index].path`. Unknown fields, watch settings and raw legacy data are retained. Notes/tag changes do not invalidate an otherwise unchanged source mapping. Stale or missing files, symbolic links, overlapping source roots and malformed/unknown sizes refuse the change. Old and new source grants and all issued row IDs are retired before storage admission; the new root must be connected explicitly. Native comparison describes names, relative paths and sizes, not video-content identity.

Protection reads and saves one encrypted per-hub timeout: Off, 1, 5, 15 or 30 minutes, with five minutes as the default. It shares the bridge's pending-operation gate and preserves video drafts. Main owns the timer and renews it only for native key, button and wheel events. DOM activity, IPC and media playback cannot keep the hub unlocked. An expired deadline cannot be extended by a late input or save; changing the policy preserves elapsed inactivity. Automatic locking uses the same destructive teardown and cleanup path as Lock hub. Off does not disable sleep or screen-lock handling.

The separate `privateCredentials.changePassword` method submits only bounded current/new passwords from the same isolated private window. It shares the gallery's pending-operation gate, rechecks exact frame/generation authority, and returns no credentials or storage diagnostics. The store verifies the current header/password and atomically replaces only the wrapped key. The session buffers queued credentials for synchronous wiping on lock, blocks competing writers/generation, and rechecks final authority. A successful request locks the session independently of window cleanup, awaits its storage drain and quarantines failed observers; late retry responses cannot reach a revoked frame.

Protection includes a collapsible three-field form. It requires saved/discarded video drafts, preserves password text exactly, clears fields before IPC and on concealment/focus loss, stops playback and keeps Lock available while pending. The new password is confirmed locally. Old copies of the hub/header retain their original password because this operation does not rotate the data key.

`privateCredentials.createUnprotectedCopy` accepts only a bounded password and explicit acknowledgement; `cancelUnprotectedCopy` cancels the current admitted copy. Both share the credential/gallery pending gate. Session reauthentication finishes and its owned password buffer is wiped before the main-owned native destination picker runs. No source or output path crosses the renderer bridge. A wrong password is retryable, successful copying keeps the encrypted session open, and cancellation/failure never promises removal of partial plaintext files.

Protection contains a separate masked-password and acknowledgement form. Video drafts and unsaved protection settings must be resolved first. Submission immediately clears the controls, pauses preview playback and keeps Cancel copy and Lock hub reachable. The native picker and exporter stay inside session/browser drainage; late selections cannot publish after revocation. An unconfirmed exporter descriptor/iterator cleanup permanently quarantines restoration, including when failure arrives after locking started.

The thumbnail/poster/filmstrip queue is limited to three simultaneous images, reserving capacity for a selected clip. Filmstrips load only after an explicit Show filmstrip action and remain confined to the selected details panel. Hiding the strip cancels its job and retries; selection changes, regeneration, protection operations and lock clear it. Late image callbacks cannot repaint a closed or replaced selection. Details alone carry the fixed filmstrip URL; no new IPC method or source authority is introduced. Page changes, selection changes and lock cancel stale UI work and remove old media sources. ## Verification boundary

Runtime tests execute production Home, ElectronService, catalogue editor and mutation services with synthetic state and stubbed Angular decorators/native UI. They cover complete snapshots, draft/IME refusal, native-result preservation, failed saves, exact releases, stale callbacks and quarantined failures. Separate Angular no-emit compilation validates templates and dependency injection. These checks do not replace the complete running application transition.

The separate `npm run test:renderer-handoff:native` harness has passed six stages using the production renderer coordinators in a sandboxed, context-isolated Electron window. It verifies native text insertion, row-draft capture, inert body/overlay controls, beforeinput/keyboard blocking, real clip pause/autoplay suppression, focus restoration, deferred native results, composition-event and invalid-draft refusal, pending invokes, repeated handoffs and failure quarantine. Its UI and main adapter are synthetic; it does not verify hardware IME, native application menus, the Angular Home/private-gallery transition or OS cache erasure.

Continue extending the actual-host native checks to reconnection, in-flight generation/playback, pending confirmations and hardware IME. Extend filesystem-save and cleanup fault coverage, and test cancellation at each transition stage, real lock/sleep, navigation and forced crashes. Verify native edit-menu behavior, real clipboard behavior, single-instance arbitration and buffer/cache observations on supported platforms.

Touch ID enrollment, removal and unlock choices remain implemented in the private documents and main-process session, with further work deferred while password-based review proceeds. See [the Touch ID guide](./private-hubs-touch-id.md) for the signing gate and the difference between synthetic-provider UI verification and real biometric acceptance.
